 # What is Git?

 In simple words, Git is a tool that helps developers track and manage changes in their code.
 
 But instead of understanding it with technical definitions, let’s take a simple real-life example.
 Suppose you have a bank passbook. That passbook keeps a record of everything:
- how much money was added
- how much money was withdrawn
- previous transactions
- current balance

In a similar way, Git keeps track of changes made in code or files. It helps developers:
- see previous changes
- manage updates
- work with other people
- keep a history of their work
  So, you can think Git like a" history tracker" of code.

  # What is Github?

GitHub is a platform or website that allows developers to store, manage, and share their projects online using Git.

To understand it in a simple way, let’s continue the same bank example.

Suppose Git is like your bank passbook that keeps track of all your transactions and history.

Then GitHub is like the bank’s online system where all that information is stored safely and can be accessed anytime.

In a similar way:
- Git tracks the changes in code
- GitHub stores and manages those projects online

It also allows developers to:
- share their work
- collaborate with others
- access projects from anywhere

## Some Basic Terms You Should Know

Just like we learn basic words before learning a new language, in the same way, there are some common terms that beginners should know before using Git and GitHub.

### 1. Repository (Repo)
A repository is like a folder where your project, files, code, and all changes are stored.

### 2. README.md
This is usually the first file inside a repository.  
It is used to write information or notes about the project.

### 3. .md (Markdown)
“.md” means Markdown.  
It helps make text look clean using headings, bullet points, code blocks, and more.

### 4. Commit
A commit means saving your work or changes in Git.

### 5. Directory
Directory simply means folder.

### 6. Push
Push means uploading your code or files to GitHub.

### 7. Pull
Pull means getting the latest files or changes from GitHub.

### 8. Clone
Clone means copying a GitHub project to your computer.

### 9. Branch
A branch allows developers to work on something new without changing the main project directly.


## How to Use Git and GitHub?

Trust me, when I first started learning Git and GitHub, things looked very confusing.

I had to watch tutorials multiple times because there were many new terms, many steps, and many things happening together.

But once I understood the basic flow, it slowly started making sense.

So let’s understand it in a very simple way.

### Step 1: Create a GitHub Account

First, go to :https://github.com (official website) and create your account.

The process is very simple, just like creating an account on Instagram, Gmail, or any other platform.

After creating your account, you will start seeing some new words like:
- repository
- README.md
- commit
- push
I explain this above .So,at first these words may look technical, but slowly they become easier to understand.

### Step 2: Install Git

Since GitHub is mainly a platform or website, we also need Git on our computer to manage and track our files.

To install Git:
- Windows users usually use Git Bash
- Mac and Linux users usually use Terminal

You can simply search:
“Download Git”

and install it according to your operating system.

### Step 3: Install VS Code

After installing Git, many beginners use : 
VS Code to write code.

If you do not have VS Code:
- download it
- install it
- complete the setup process

There are many tutorials available for installation, so the setup part may take a little time in the beginning.

But do not worry too much about mastering everything immediately.

### Step 4: Connect GitHub with VS Code

After setting everything up, the next step is connecting GitHub with VS Code using Git.

In simple words:
- VS Code is where you write the code
- Git tracks the changes
- GitHub stores the project online

This connection helps you upload your code from your computer directly to GitHub.

### Step 5: Configure Git

Before using Git properly, we usually configure it with our name and email.

This helps Git identify who is making the changes.

Some common commands are:

git config --global user.name "Your Name"

git config --global user.email "your_email@example.com"

### Local vs Global Configuration

Git configuration has two types:

1. Local Configuration
- Works only for one specific project or repository

2. Global Configuration
- Works for all repositories on your computer

Most beginners usually use global configuration because it is simpler and does not need to be repeated again and again.

### Step 6: Create a Repository

Now you can create your first repository on GitHub.

A repository is simply a folder where your:
- code
- notes
- projects
- articles
- files

are stored.

### Step 7: Add, Commit, and Push

After writing code or making changes, Git usually follows three common steps:

1. Add  
Select the files you want Git to track.

2. Commit  
Save the current changes.

3. Push  
Upload those changes to GitHub.

This is how your local project gets updated online on GitHub.

At first the process may look difficult, but after practicing a few times, it slowly becomes normal.

## Some Common Myths About GitHub

Before learning GitHub, I used to think that GitHub was something very difficult and only experienced programmers could use it.

But after exploring it, I realized that many of these thoughts were just myths.

### Myth 1: GitHub is only for experts

This is probably the most common myth.

Many beginners think they need to master programming before using GitHub.

But that is not true.

Even if you are just starting your programming journey, you can still use GitHub to:
- store your notes
- upload simple programs
- document your learning
- practice consistency

You do not need to be an expert to start.

### Myth 2: GitHub is very hard to use

At first, GitHub may look confusing because there are many new terms like:
- repository
- commit
- push
- branch

But slowly these things become easier with practice.

Just like any other platform, once you use it regularly, you start understanding it naturally.

### Myth 3: Only coders can use GitHub

Many people think GitHub is only for writing huge projects or advanced code.

But people also use GitHub for:
- notes
- articles
- documentation
- learning journeys
- small projects

You can even use GitHub to track what you learn daily.

### Myth 4: Your GitHub profile needs to look perfect

Many beginners compare their profiles with experienced developers and feel scared to start.

But every developer once started as a beginner.

A simple and active profile is much better than waiting for perfection.

### Myth 5: You need to know everything before starting

This is not true at all.

Most people learn GitHub while using it.

You do not have to understand every command or every feature on day one.

Start small, practice regularly, and slowly things begin to make sense.

In simple words, GitHub is just a tool.

The more you use it, the more comfortable you become with it.
